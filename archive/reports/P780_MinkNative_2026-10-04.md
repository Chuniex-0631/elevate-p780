## JNI 边界

libmink-sock-native-api.so 的动态依赖包含 libminksocket_system.so、libjnihelpers.so，以及 log/C++/C/math/dl 常用库。

nativeGetMinkOpener.cfi @ 0x2218：

- 接收 Java 传入 fd 与 openerHandle。
- 0x22bc 调用 MinkSocket_new(NULL,NULL)。
- 0x22cc 调用 MinkSocket_start(socket, fd)。
- 0x22e8 调用 MSForwarder_new(socket, openerHandle)。
- 将返回的对象函数指针和 context 存入 16 字节结构，并包装成 CMinkObject。

因此这里包装的是服务端提供的 fd/句柄；没有证据表明客户端可自行构造一个有效的授权对象。

nativeCheckFd.cfi @ 0x3054：调用 fcntl(fd,1)，即 F_GETFD，并检查返回值及 errno==9（EBADF）。这段检查没有读取调用方签名或 OEM 解锁状态。汇编显示对 errno 的检查也出现在 fcntl 非 -1 返回分支；不能将此检查描述成完备的 socket 身份认证。

CMinkObject.nativeInvoke.cfi @ 0x24c4：封送 Java buffers / object arrays，构造参数计数，对对象的 invoke 函数指针执行间接调用（0x2c9c），将非零结果走 InvokeException 路径。可见范围内是通用对象调用桥接，不是 PFM 许可证校验实现。

## Socket 层与身份信息

MSForwarder_new.cfi @ 0x7cb0 创建保存 socket 与对象 handle 的转发对象。

MSForwarder_invoke.cfi @ 0x7b98：普通操作路径在 0x7bd0 调用 MinkSocket_invoke(socket, handle, op, args, counts)；另有引用管理等特殊操作分支。

MinkSocket_start.cfi @ 0x7a8c：

- 0x7ae0 调用 getsockopt(fd,1,17,&cred,&len)，长度初始为 12；对应 SOL_SOCKET / SO_PEERCRED。
- 成功后保存凭据中的 UID/GID，并设置有效标记。
- dispatch 将保存的身份信息挂到线程局部变量；MinkIPC_getClientInfo.cfi @ 0x4c68 从线程局部变量读取信息。

这证明此传输层有对端身份信息机制；不证明上层一定执行了某个白名单，也不证明白名单是什么。经 Binder 传递的 socket fd，其 socket 对端凭据不能自动等同于当前 Binder 调用者身份；须结合 TZAccessService 的 request 实现、socket 创建方式及后端处理核对。

库中出现 SMCINVOKE_IOCTL_LOG 日志文本，不能仅凭文本断言此客户端库直接访问 /dev/smcinvoke 或已完成安全世界调用。已定位的主路径是 socket 对象转发。
