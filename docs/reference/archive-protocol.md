# P780 证据归档规范

本仓库用于长期交接与跨对话续接。所有研究条目最少应说明：

1. **日期/测试环境**：实机 Android 固件与内核，或离线候选源码 commit。
2. **来源等级**：真机命令回显、用户提供的文件、软件逆向/静态分析、公开网页、模型推断。
3. **原始证据**：文件名、原始字节数、已验证的 SHA-256（如实际计算过）；仅见文件名则不要写内容已归档。
4. **实验输入与方法**：尽量只读、可重复、原命令和边界条件。
5. **实际结果**：成功/失败回显、输出路径或 GitHub Actions Run/Job ID。
6. **禁止混淆**：原源码不同版本、两台设备不同硬件、编译产物与真实运行内核、可列目录与可读文件。
7. **隐私筛查**：序列号、IMEI、电话号码、认证 token、私钥、个人通信/账号数据不得进入提交历史。
8. **不可逆风险**：任何涉及 EDL 写入、bootloader、分区操作、实机崩溃的尝试应作为独立待评估项，不得照搬网页命令。

## 目录与动态维护

- [文档导航](../README.md)：docs 根目录保留 STATUS、NEXT_STEPS、HISTORY、EVIDENCE_MANIFEST；research 为持续专题，reference 为来源/规范，archive 为早期阶段记录。
- [证据索引](../../evidence/README.md)：device 为原始配置/Tracefs，actions 按运行编号分组，framework/journey 区分原件身份、转换视图与分析结果，restricted 仅为敏感资料分类标签。
- [旧资料](../../archive/README.md)：完整历史报告/设备摘要与历史脚本；[当前工具](../../tools/README.md) 独立维护。

每一阶段同步专题、状态、证据/来源、README 导航与 CHANGELOG；修订旧结论，归位重复/失效内容，不只追加新报告。现有原始 ZIP/JAR 不为美化结构随意重打包；文本转换必须标明原编码与来源。历史快照保留时间背景，不能用旧计数冒充当前全库验收。

不同运行相同字节通常具有独立来源，不只凭 SHA 删除；重复阅读格式可以在标明映射后合并。本轮恢复快照：[archive/pre-restructure-20261011](https://github.com/Chuniex-0631/p780-kernel-research/tree/archive/pre-restructure-20261011)，较早快照仍保留。

候选构建和历史导入工作流仅手动触发，避免整理文档时重跑实验；归档完整性检查继续自动运行。研究待机期间仅有实质新增线索才更新提交，原厂参数阻断保持明确。

## 版本语义

在没有当前固件原厂内核二进制或逐构建符号证据时，GhostLock 的目标设备适配保持 `BLOCKED`；如果某个独立对象编译成功，也只是该对象在选定候选树和工具链中的构建结果。

未来将完整固件数据导入时，先生成单独来源/哈希清单，并在 `docs/STATUS.md` 标明它与真实设备版本匹配到何种程度。
