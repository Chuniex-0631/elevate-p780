总计 **5,716,112,384 字节**（十进制 5.716 GB）。`product.tar` 按两个分卷顺序拼接，预期长度 **3,258,192,896 字节**；归档前期记录的完整文件 SHA-256 为 `69719f6550da0dd1409622bab67aeed672c874a200330fdc492229f52321904b`，位于 `SHA256SUMS.txt`。此完整文件 SHA 尚**未在本轮由二进制重算**。

`SHA256SUMS.txt` 的 `product.tar` 是拼接后完整文件的摘要，不包含两个 Release 分卷的独立摘要；分卷 SHA-256 以 `release-assets.json` 为准。该清单同时列有不在本次 Release 的本地源文件及补充文件，不能把它全部当作七个 Release 资产的清单。

## 3. 采集覆盖边界

原采集文档报告分区枚举/读取失败：`system` 95、`product` 5、`system_ext` 15、`vendor` 2,127（具体范围和统计口径见原采集报告）。尤其不能因 `vendor.tar` 接近某次 `du` 的总字节就认为 vendor 文件全覆盖：缺失文件可能很小但很关键。

`meta1.tar` 记载 68 个文件条目，包括编号碎片和状态/标记文件；不能把它算作独立、可刷写分区。

`kernel.Image` 是 ARM64 内核镜像本体，不是 `boot.img` 或 `super.img`。对应符号独立核验成果见 `docs/research/p780-kernel-symbol-recovery-20261025.md`。

## 4. 可复现的本地二进制复核

仓库新工具：[`tools/rom/verify_release.py`](../../tools/rom/verify_release.py)。仅使用 Python 标准库；默认**只读**已下载文件；`--merge-product` 才会创建新的 `product.tar`（拒绝覆盖）。

```powershell
# 已在本机克隆仓库，且七个 Release 资产都位于 D:\P780-ROM
python tools/rom/verify_release.py "D:\P780-ROM" --merge-product
```

检查：每个 Release 文件的 SHA-256/大小；两分卷拼接后 `product.tar` 的 SHA-256/大小；逐 TAR 读取普通文件路径和长度，与 manifest 对照，并检查重复路径、目录穿越和链接目标。不解包文件、不写手机、不请求 Root。对于已经存在的 `product.tar`，脚本不会覆盖它。

**本次脚本只通过了人工构造的小型归档测试，没有在真正的 5.7 GB 资产上运行。** 在出现本机运行日志前，不能将本阶段标为“二进制 PASS”。

## 5. 审计结论与下一步

- **已核验**：Release 七个资产存在；元数据与 JSON 一致；文本清单分区数目自洽；32 项缺口未误填。
- **待本地运行**：七文件实算 SHA-256、Product 拼接摘要、TAR 目录与普通文件元数据逐项比对。
