## 1. 已记录 A/B 是不同 build

- 当前系统（B）：`ro.build.fingerprint = .../264:user/release-keys`；
- 原厂 `vbmeta_a.00.bin` 的 prop 描述符：

  ```
  com.android.build.vendor.fingerprint = .../263:user/release-keys
  com.android.build.boot.fingerprint   = .../263:user/release-keys
  ```

  即 **A = 263，B = 264**，A 是上一版，符合 A/B 设备"旧槽保留上一 build"的规律。

## 3. 为什么拿包没有帮助

- 即使拿到 OTA，包是 **release key（RSA-2048）** 签名的，不能改成 rooted；
- 最新 OTA 只包含 **264 及之后**的 boot，不会包含 A 槽的 **263** boot；
- 要恢复 A 的 263，需要**历史 OTA/工厂包**，公开渠道没有；
- 已有 metadata 验签通过和 boot_a 有限写入的摘录，非任意块写。缺口包括目标槽镜像配套、实际切槽返回及存储后端；slot 元数据不应预设在 misc。

## 4. 结论

- 截至该轮未取得可用 OTA 包；不能据此证明所有历史/后续来源不存在；
- 尚未取得完整恢复/同步 A 的材料；并非已证明无法恢复；
- 后续先复核 Boot HAL/GPT 与 ABL 回退；loader 或 misc 写入本身都不保证刷写启动；
- **历史主线切回 6931 的建议已暂停**；运行时完整权限与永久 Root 分别验收，当前首要任务见启动链复核。
