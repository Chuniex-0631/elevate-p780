# P780 新攻击面复核：KGSL 与 FastRPC（2026-10-27）

> 背景：update_engine 切槽 no-op；6931 的 values 放置不可控；EDL 缺签名 loader。
> 本轮重新评估 Qualcomm 驱动攻击面，目标仍是完整 root。

## 1. 设备事实

- 内核：`5.4.233-qgki-gea5245e94afe-dirty`，构建时间 2024-02-20；
- SPL：2024-02-01；
- GPU：Adreno 619v1；
- `/dev/kgsl-3d0`：`crw-rw-rw-`，shell 可 `open()` 成功；
- `/dev/adsprpc-smd`：`crw-rw-r--`，shell 可 **O_RDONLY** 打开；
- 未知 ioctl 返回 `ENOTTY`，说明 **read-only fd 仍会进入 fastrpc 的 unlocked_ioctl**。

## 2. KGSL：有入口，但已知 2024 漏洞不适用

- 内核符号只有 `kgsl_ioctl_gpuobj_alloc/import/free/map_user_mem` 等，
  **没有 VBO 相关符号**（`kgsl_gpuobj_bind`、`kgsl_vbo*` 均不存在）；
- CVE-2024-23380 / 23373 / 23384 都围绕 VBO，本机驱动不支持 VBO；
- CVE-2025-21479 只影响 Adreno A7xx，本机是 A619（A6xx）；
- 结论：KGSL 不是当前最高概率路径。

## 3. FastRPC：新主线候选

### 3.1 可达性

- `/dev/adsprpc-smd` 权限 `crw-rw-r--`；
- shell `open(O_RDONLY)` 成功（fd=3）；
- 未知 ioctl 返回 `ENOTTY`，说明 ioctl 已进入驱动；
- 已知符号：`fastrpc_mmap_create/free`、`fastrpc_internal_mmap/munmap`、
  `fastrpc_internal_invoke`、`compat_fastrpc_device_ioctl`、
  `compat_get_fastrpc_ioctl_invoke2`。

### 3.2 时间窗

- 本机内核 2024-02 / SPL 2024-02；
- CVE-2024-43047（ITW，map collision UAF）与 CVE-2024-21455
  （compat `is_compat` 指针混淆）都在 2024 年下半年修复；
- **本机大概率仍受影响**。

### 3.3 CVE-2024-21455 要点

Project Zero 分析：

- `compat_fastrpc_device_ioctl()` 会把 `fl->is_compat = true`，且**永不恢复**；
- 32 位进程在共享 fd 上调用一次 compat ioctl 后退出；
- 64 位进程继续用同一个 fd 调 64 位 invoke2；
- 驱动仍按 `is_compat` 用 `memmove` 访问 `inv2->invparam`，
  把它当作**内核指针**，而不是 user 指针。

潜在能力：

- `K_COPY_FROM_USER` 变成 `memmove`：从任意内核地址读；
- 若后续 `K_COPY_TO_USER` 也走 `memmove`，则可能写任意内核地址；
- 可先用安全目标（`selinux_state` / `init_cred`）验证读，再构造写。

### 3.4 CVE-2024-43047 要点

- `get_args` 的 handle 引用与 `put_args` 的 fdlist 查找不是同一个 map；
- 构造 map collision（大 map 覆盖小 map）使 `put_args` 错误释放仍被
  context 引用的 `fastrpc_mmap`；
- 标准 UAF，后续可用 slab 喷 `fastrpc_mmap` 改指针；
- 分析公开，但没有公开 PoC；实现量比 21455 大。

## 4. 计划

### Phase 1：确认版本与接口

1. 取 5.4 的 `adsprpc.c` / `adsprpc_compat.c` / `fastrpc.h`；
2. 确认本机 ioctl 表、`is_compat` 路径、`invoke2` 结构；
3. 用只读 ioctl（GET_DSP_INFO/INIT）确认 O_RDONLY 下可达。

### Phase 2：CVE-2024-21455 读探针

1. 32 位子进程在共享 fd 上触发 compat ioctl，设置 `is_compat`；
2. 64 位父进程调用 invoke2，`invparam` 指向一个**安全内核地址**
   （先选只读、不会崩的全局，如 `selinux_state` 或 `init_cred`）；
3. 观察是否发生内核读、返回什么、是否 panic；
4. 不写任何东西。

### Phase 3：读→写

- 若读成功，找 `K_COPY_TO_USER`/`put` 路径；
- 目标：`selinux_state` 首字节写 0（permissive），或 cred uid；
- 仍走最小写、单次验证。

### 失败/回退

- Phase 2 若 panic 或不可达：转 CVE-2024-43047（UAF + slab 喷）；
- 两者都不行：停止内核路线，保留 uid0 shell / EDL 线索。
