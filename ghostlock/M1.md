# M1：PI 链构造探针

## 目的

确认在 `u:r:installd:s0`（uid 0）里能构造出 rt_mutex 的 PI 等待链，
并用 `/proc/self/task/<tid>/stack` 观测到 `rt_mutex` 栈帧。

## 原理

三个线程三把 `PTHREAD_PRIO_INHERIT` 互斥锁：

```
T1 持 M1
主线程 阻塞在 M1 上      → waiter(current)
T2 持 M2，稍后阻塞在 M1 → 形成链
T3 持 M3，稍后阻塞在 M2
```

阻塞后读 `/proc/self/task/<tid>/stack`，若看到
`rt_mutex_adjust_prio_chain` / `__rt_mutex_slowlock` 等帧，说明 `pi_blocked_on` 已置位。

## 构建与运行

```bash
aarch64-linux-android30-clang -O2 -static -pthread m1_pi_chain.c -o m1_pi_chain
# 通过现有注入通道投递到 /data/local/tmp，再以 uid 0 的 sh 执行
./m1_pi_chain > /data/local/tmp/m1.log 2>&1
```

## 通过判据

- 日志里出现至少一条 `rt_mutex` 相关栈帧；
- 进程不崩溃、无 SELinux 拒绝（`/proc/<tid>/stack` 需要 uid 0，我们满足）。

## 失败时的下一步

- 若 `stack` 读不到：改用 `/proc/<tid>/wchan` 或 `/proc/<tid>/stat` 的 blocked 字段；
- 若链构造不出来：检查 `PTHREAD_PRIO_INHERIT` 是否被 bionic 支持（Android 自 5.0 起支持）。
